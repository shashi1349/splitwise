# Deployment guide

This document is the runbook for putting Splitwise-Lite on the public
internet. The repo ships with everything required (Dockerfiles, blueprint
configs); the steps below are the ones a human still needs to drive.

> **Honest note:** the Kiro session that built this project doesn't have
> Render or Vercel credentials, so the README's "live demo" links are
> placeholders. Once you finish the steps below, swap them in and the
> rest of the docs will be accurate.

---

## 1 — Local stack (no signup needed)

```bash
git clone https://github.com/shashi1349/splitwise.git
cd splitwise
docker compose up --build
```

After the build:

| Service  | URL                                          |
| -------- | -------------------------------------------- |
| Frontend | <http://localhost:5173>                      |
| Backend  | <http://localhost:8080>                      |
| Swagger  | <http://localhost:8080/swagger-ui.html>      |
| Health   | <http://localhost:8080/actuator/health>      |
| Postgres | `postgres://splitwise:splitwise@localhost:5432/splitwise` |

Stop with `docker compose down` (or `down -v` to wipe the database).

---

## 2 — Backend on Render (Docker + managed Postgres)

1. Push this repo to GitHub.
2. In the Render dashboard click **New → Blueprint** and pick the repo.
   Render reads `render.yaml` at the root and provisions:
   - a free PostgreSQL instance named `splitwise-db`
   - a free web service named `splitwise-api` that builds
     `backend/Dockerfile`
   - all DB env vars wired into the web service automatically
3. After the build finishes, copy the generated URL
   (e.g. `https://splitwise-api.onrender.com`) — you'll need it for the
   frontend in the next step.
4. **Important:** in **Environment** for `splitwise-api`, set
   `APP_FRONTEND_ORIGIN` to your future Vercel URL
   (e.g. `https://splitwise-lite.vercel.app`). Save and redeploy.
5. Verify:
   ```bash
   curl https://splitwise-api.onrender.com/actuator/health
   # {"status":"UP"}
   ```
6. The Swagger UI is published at `/swagger-ui.html`. Click **Authorize**
   in Swagger after a successful `POST /auth/login` to call protected
   endpoints from the docs page.

`JWT_SECRET` is auto-generated by Render and never returned to the
caller. Rotating it forces all existing tokens to fail signature
verification, which is the desired behaviour for a security event.

---

## 3 — Frontend on Vercel

1. In Vercel, **Add New → Project**, import the same GitHub repo.
2. **Root directory:** `frontend`. Vercel auto-detects the Vite preset
   (and the repo also ships `frontend/vercel.json` which makes the SPA
   fallback explicit).
3. **Environment Variables:**
   - `VITE_API_BASE_URL` = the Render URL from step 2
     (e.g. `https://splitwise-api.onrender.com`)
4. Deploy. Vercel will give you `https://<project>.vercel.app`.
5. Go back to Render, set `APP_FRONTEND_ORIGIN` to that Vercel URL, and
   redeploy the backend service so CORS allows the new origin.

## 4 — Smoke-test the deployed stack

```bash
APP=https://splitwise-api.onrender.com

# Register
curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"email":"alice@example.com","displayName":"Alice","password":"alicepass1"}' \
  $APP/auth/register

# Login
TOKEN=$(curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"email":"alice@example.com","password":"alicepass1"}' \
  $APP/auth/login | jq -r .token)

# Authenticated call
curl -s -H "Authorization: Bearer $TOKEN" $APP/groups
```

Then open the Vercel URL in a browser, register/login, create a group,
add a member, add an expense, and confirm the Balances and Settle Up
tabs show what you expect.

## 5 — Rotating secrets / wiping data

| Action | How |
| ------ | --- |
| Rotate JWT secret | Render → service env vars → regenerate `JWT_SECRET` → redeploy. All existing tokens become invalid. |
| Reset DB | Render → database → **Reset** (wipes data, keeps schema migrations on next boot). |
| Bump CORS origin | Update `APP_FRONTEND_ORIGIN` and redeploy backend. |

---

## 6 — Things I deliberately left out (and why)

- **TLS termination, custom domain.** Render and Vercel both terminate
  TLS for you out of the box; no additional work needed unless you want
  a custom domain. Both providers walk you through that in their UI.
- **Centralised log aggregation.** The CorrelationIdFilter already
  stamps every log line with a request id; pick up the logs from
  Render's log stream into Datadog / Logtail / similar when traffic
  warrants it.
- **Auto-scaling.** Free tier is single-instance. The app is stateless
  (JWT, no sessions) so horizontal scaling is just a slider in the paid
  tier.
